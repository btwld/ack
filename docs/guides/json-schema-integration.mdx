title: JSON Schema Integration
---

Your Ack [schema](../core-concepts/schemas.mdx) already describes your data's shape — so you can export it as JSON Schema (Draft-7) and reuse it to document an API, drive a form library, or define an LLM tool, all from one source of truth.

## Importing published schemas

Use strict `Ack.fromJsonSchema()` to turn a decoded JSON Schema document
(a map or boolean, not a JSON string) into an
`AckSchema<Object, Object>`. The input dialect is draft 2020-12 or Draft-7
(`http(s)://json-schema.org/draft-07/schema(#)`), including when `$schema` is
absent. Other explicitly declared dialects are rejected.

Only the declared `$schema` string is checked — a document is never matched
against a dialect by shape. Draft-7 documents are evaluated under the same
supported subset: tuple-form `items` (a Draft-7 array) is rejected, and `$ref`
siblings are applied as in draft 2020-12. Draft-4 boolean `exclusiveMinimum`
and `exclusiveMaximum` values are rejected, and Draft-4 `integer` rejects `1.0`
where this importer accepts it.

```dart
import 'package:ack/ack.dart';

final AckSchema<Object, Object> schema = Ack.fromJsonSchema({
  'type': 'object',
  'properties': {
    'name': {'type': 'string'},
    'age': {'type': 'integer', 'minimum': 0},
  },
  'required': ['name'],
  'additionalProperties': false,
});

final user = schema.parse({'name': 'Ada', 'age': 36});
final exported = schema.toJsonSchema();
```

The returned abstract `AckSchema<Object, Object>` composes with native
Ack schemas; its runtime implementation is internal. It validates JSON values
without injecting defaults or applying coercions. Parsing returns a detached,
recursively unmodifiable value.
Required means **key present**, not **non-null**; an omitted `type` does not
implicitly require an object, string, or array. Integral numbers such as `1.0`
match `integer`, and null array elements are supported.

### Design: reuse the existing export boundary

`AckSchema.toJsonSchema()` remains the export API. Imported schemas participate
in the same `AckSchema` → `AckSchemaModel` → JSON Schema path as native schemas;
the builder bridge delegates to that path too. There is no second public
exporter or dependency on a Flutter runtime.

You can import an existing export directly:

```dart
final document = Ack.object({'name': Ack.string()}).toJsonSchema();
final AckSchema<Object, Object> schema = Ack.fromJsonSchema(document);
final exportedAgain = schema.toJsonSchema();
```

The source document and executable validator are distinct.
`Ack.fromJsonSchema()` is the single import entry point and always imports
strictly. The importer preserves supported JSON validation semantics,
not the original Dart declaration: JSON cannot recover codecs, Dart model
types, custom callbacks, or refinements that were absent from the export.
Exports containing unsupported keywords are rejected.

### Importing `format`

Ack's strict supported-subset importer recognizes Ack's exported string formats
(`date-time`, `date`, `email`, `uuid`, `uri`, `ipv4`, `ipv6`) and standard
numeric format ranges (`int32`, `int64`, `uint32`, `uint64`, `float`, `double`),
and validates them automatically:

```dart
final timestamp = Ack.fromJsonSchema(
  {'type': 'string', 'format': 'date-time'},
);
timestamp.parse('2024-02-29T12:34:56.123456789+02:00');
```

Other format labels remain unsupported and produce an `unsupported_keyword`
diagnostic at their source location. This is Ack's strict import subset, not a
claim that draft 2020-12 requires format assertions or that Ack implements the
full Format-Assertion vocabulary. A format-only schema still accepts values of
other types because `format` does not imply a `type`; add `type` when needed.

Date-time validation uses RFC 3339 syntax, calendar dates, offsets, and the
bundled list of announced positive leap-second dates. The list is updated in
Ack releases when IERS announces new leap seconds; validation never fetches
data at runtime. Parsing preserves the original string, including its
fractional precision and offset. It does not convert it to a Dart `DateTime`.

Export retains `format` in imported schemas. Reimport through the same strict
Ack importer to keep validation behavior. External JSON Schema validators may
treat `format` as an annotation unless configured to assert it.

### Supported import subset

| Area | Keywords |
| --- | --- |
| Schemas and types | Boolean schemas, `type` (including lists and `null`) |
| Equality | `enum`, `const`, including nested JSON values and empty enums |
| Objects | `properties`, `required`, boolean/schema `additionalProperties`, `propertyNames`, `minProperties`, `maxProperties` |
| Arrays | Single-schema `items`, `contains`, `minItems`, `maxItems`, `uniqueItems` |
| Strings | `minLength`, `maxLength` (Unicode code points), `pattern` (unanchored ECMA-262 search in Unicode mode) |
| Numbers | `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf` (exact decimal division) |
| Composition | `anyOf`, `allOf`, exclusive `oneOf`, `not`, `if`/`then`/`else`; sibling assertions are intersected |
| References | `$ref`, `$dynamicRef`, `$id`, `$anchor`, `$dynamicAnchor`, `$defs`, `definitions`; local/cross-document pointers and structural recursion |
| Annotations | `title`, `description`, `default`, `examples`, `$comment`, `readOnly`, `writeOnly`, `deprecated`, `format`, content keywords, unknown extensions |

`pattern` uses Unicode-mode matching, including Unicode property escapes.
Imported schemas do not coerce instance values or inject `default` values.

The complete required draft 2020-12 test suite passes for source validation
and export/re-import. Optional vocabulary coverage remains partial; the
repository capability matrix tracks the per-vocabulary limits.
`format` is an annotation by default. Pass `assertFormats: true` to enforce
supported formats, or supply a dialect requiring the format-assertion
vocabulary. Unknown asserted formats fail compilation. Standard 2020-12
meta-schema resources resolve offline.

### References and bundles

Supply decoded documents by retrieval URI. Relative keys and references resolve
against `baseUri`; nested `$id` values establish new resource scopes. When no
base is provided, the importer uses `ack-import:///root.json`. The importer
never reads files or fetches URLs.

```dart
final AckSchema<Object, Object> schema = Ack.fromJsonSchema(
  {r'$ref': r'types.json#/$defs/message'},
  baseUri: Uri.parse('https://example.com/protocol/root.json'),
  documents: {
    Uri.parse('types.json'): {
      r'$defs': {
        'message': {
          'type': 'object',
          'properties': {'text': {'type': 'string'}},
          'required': ['text'],
        },
      },
    },
  },
);
```

Exports preserve imported Draft 2020-12 resources by default (`toJsonSchema()`
and `toSchemaModel()`). To lower compatible imported schemas into Draft-7
`definitions` and rewritten references, call `toJsonSchemaDraft7()` or
`toSchemaModelDraft7()`; imported schemas that require 2020-12-only semantics
reject Draft-7 lowering explicitly. Validation equivalence is the contract,
not textual identity. Imported schemas can be nested inside native objects and
combined with other imported or lazy schemas without losing reference scope.
Explicit JSON Pointers may also target schemas inside extension containers,
such as A2UI's `#/components/Text`. Such containers are not scanned as schemas
unless referenced.

### Import failures and diagnostics

Unsupported features throw
`JsonSchemaImportException`, whose `diagnostics` identify each source document,
keyword, JSON Pointer, reason code, and explanation. Assertion diagnostics
cover the validation graph reachable from the imported root. Unsupported
assertions in unused definitions or unrelated supplied documents do not make
the import fail. Schema resource IDs still need to be unambiguous.

Malformed supported keywords, unresolved references, duplicate resource IDs,
unsupported dialects, and reference cycles that do not descend into an instance
are errors. The importer checks schema structure and the keywords it compiles;
it is not full meta-schema validation of unused definitions or unsupported
vocabularies. Structural recursion is supported without adding an arbitrary
validation-depth constraint.

### Validation errors

When a value fails a keyword of an imported schema, the error is a
`JsonSchemaValidationError`. It names the failing keyword and locates it in the
source schema, so callers do not parse the message:

```dart
final schema = Ack.fromJsonSchema({
  'properties': {
    'tags': {
      'items': {'enum': ['x', 'y']},
    },
  },
});
final error = schema.safeParse({'tags': ['x', 'z']}).getError();
if (error is JsonSchemaValidationError) {
  print(error.keyword); // enum
  print(error.documentUri); // ack-import:///root.json
  print(error.pointer); // #/properties/tags/items/enum
  print(error.keywordLocation); // /properties/tags/items/enum
  print(error.path); // #/tags/1
}
```

`documentUri` and `pointer` follow `$ref` into the referenced document, and
use the same form as `JsonSchemaImportDiagnostic`. The pointer starts at the
document root, also inside a subschema that declares its own `$id`. `keyword`
is empty when the failing subschema is `false`. Only the first failure is
reported. A root `null` that the source schema rejects returns the standard
`SchemaConstraintsError` for a missing value, as other non-nullable Ack schemas
do.

`keywordLocation` is the evaluation path from the root schema to the failing
keyword. It includes each `$ref` it passed through, so two applicators that
share a definition report different locations, while their `pointer` is the
same. It uses the plain JSON Pointer form of the Draft 2020-12
`keywordLocation` output field, with no `#` and no percent-encoding. It is
empty when the root schema is `false`.

### Importing json_schema_builder models

The existing bridge works in both directions:

```dart
import 'package:ack/ack.dart';
import 'package:ack_json_schema_builder/ack_json_schema_builder.dart';
import 'package:json_schema_builder/json_schema_builder.dart' as jsb;

final AckSchema<Object, Object> ackSchema =
    jsb.Schema.string(minLength: 2).toAckSchema();
final builderSchema = ackSchema.toJsonSchemaBuilder();
```

`toAckSchema({baseUri, documents, assertFormats})` returns the validator
directly. It accepts `Map<Uri, jsb.Schema>` bundles. Formats are annotations
unless `assertFormats: true` or a supplied dialect enables assertions.

MCP registration compatibility is deferred to separate work; importing a
schema does not establish compatibility with a tool-registration API.

### A2UI compatibility and verification

Offline regression fixtures pin five representative A2UI v0.9 protocol schemas
to upstream commit `f5e945a93da36a5d126228f2ad6fbe68809ef8f7`.

The basic catalog is **not an exact supported import**: it additionally uses
unevaluated-property checks, conditionals, formats, and an extension
keyword. Import therefore fails with diagnostics. The client event schema
imports successfully and validates its action timestamp as `date-time`, while
client capabilities report the three meta-schema references. Test the specific
catalog your application uses; successful validation of examples does not prove
complete catalog conformance.

The supported-subset fixture contains 678 upstream JSON Schema instance cases
across 205 groups, including supplied remote documents. A separate optional
date-time fixture adds 43 cases. The supported-subset tests check parse,
encode, and re-imported exports without network access. Unsupported cases are
not silently skipped within that fixture.

## Generating Dart models from draft 2020-12

Enable the opt-in `ack_generator:ack_json_schema` builder for a
`*.schema.json` source. In `model_mode: auto` it retains typed `@AckInfer`
fields and `copyWith` for the representable v1 subset. A valid schema with
other 2020-12 behavior generates validated value models instead; their
`value` holds immutable JSON and their `parse`, `safeParse`, `encode`,
`safeEncode`, and `toJson` methods use the source validator. Set
`model_mode: validated` to force this exact path even for simple shapes,
including the typed `int` and UTF-16 string-length edge cases.

The builder also accepts `assert_formats: true` and an offline `documents`
mapping from retrieval URI to package-local JSON asset path. It never fetches
URLs. Source `$defs` generate named models, and a validating document root
generates `Root`; arbitrary definition keys get stable Dart class names.
Unknown required vocabularies, unsupported asserted formats, malformed
schemas, and unresolved resources fail the build with JSON-pointer diagnostics.
See the [generator package README](https://pub.dev/packages/ack_generator)
for `build.yaml` syntax. The required 2020-12 corpus generates offline with
its supplied resources; generated runtime parity is also exercised in a real
`build_runner` consumer for representative advanced features.

## Generating JSON schemas

Call `toJsonSchema()` on any `AckSchema` instance. This is the same generic Draft-7 renderer used by `schema.toSchemaModel().toJsonSchema()`.

```dart
import 'dart:convert';

import 'package:ack/ack.dart';

enum UserRole { admin, user, guest }

final userSchema = Ack.object({
  'id': Ack.integer().positive().describe('Unique user identifier'),
  'name': Ack.string()
      .minLength(2)
      .maxLength(50)
      .describe("User's full name"),
  'email': Ack.string().email().describe("User's email address"),
  'role': Ack.enumValues(UserRole.values).withDefault(UserRole.user),
  'isActive': Ack.boolean().withDefault(true),
  'tags': Ack.list(Ack.string()).unique().describe('List of user tags').nullable(),
  'age': Ack.integer().min(0).max(120).nullable().describe("User's age"),
}).describe('Represents a user in the system');

void main() {
  // Convert the AckSchema to a JSON Schema Object Map
  final jsonSchemaMap = userSchema.toJsonSchema();

  // Pretty print the JSON representation of the JSON Schema
  final jsonEncoder = JsonEncoder.withIndent('  ');
  print(jsonEncoder.convert(jsonSchemaMap));
}
```

> **Building an adapter package?** Most users only need `toJsonSchema()`
> (above). To convert Ack schemas to another target format, render from
> `schema.toSchemaModel()` (the canonical `AckSchemaModel`) rather than the JSON
> Schema map. Start with the [adapter quickstart](./schema-converter-quickstart.mdx),
> then use the [complete adapter authoring guide](./creating-schema-converter-packages.mdx)
> for architecture and testing guidance.

## Adapter model

Use `toSchemaModel()` for a reusable, target-independent view of an Ack schema:

```dart
final model = userSchema.toSchemaModel();
final jsonSchemaMap = model.toJsonSchema();

for (final warning in model.warnings) {
  print('${warning.code}: ${warning.message}');
}
```

`AckSchemaModel` describes the boundary values a schema accepts and exports, keeping adapter metadata such as property ordering and discriminator info. Its JSON Schema renderer emits only generic Draft-7-compatible output; provider-specific hints belong in adapter renderers.

## Shape stability notes

`toJsonSchema()` renders generic Draft-7 JSON Schema with stable nullability rules:

- Primitive/object/list/enum schemas marked with `.nullable()` are emitted as:
  - `anyOf: [<base-schema>, { "type": "null" }]`
- `Ack.anyOf([...]).nullable()` is emitted as
  `anyOf: [{ "anyOf": [...] }, { "type": "null" }]`
- `Ack.discriminated(...)` is emitted as `anyOf` with effective object
  branches. Each branch contains the exact required discriminator `const`.
- `Ack.discriminated(...).nullable()` wraps that `anyOf` union with a second
  `{ "type": "null" }` branch.
- `Ack.lazy(name, ...)` is emitted as a Draft-7 `definitions` entry and local
  `$ref` values such as `{ "$ref": "#/definitions/Category" }`.
- Non-null lazy refs that carry metadata such as `description` use `allOf`
  around the `$ref` so Draft-7 validators do not ignore that metadata as a
  `$ref` sibling. Nullable lazy refs keep metadata beside the top-level `anyOf`.

This means nullable enums are represented as:

```json
{
  "anyOf": [
    { "type": "string", "enum": ["admin", "user", "guest"] },
    { "type": "null" }
  ]
}
```

And nullable discriminated unions are represented as:

```json
{
  "anyOf": [
    { "anyOf": [/* effective discriminated object branches */] },
    { "type": "null" }
  ]
}
```

If you build consumers that inspect generated schemas, treat nullability and union composition as separate concerns and don't assume enum values always live at the top level.

The nested nullable-union shape is intentional for generic Draft-7 output and matches Zod v4's `toJSONSchema()` renderer. Don't flatten it in `AckSchema.toJsonSchema()`; provider-specific adapters that need a different shape should implement explicit adapter rendering.

**Limitations:**

-   **Custom Constraints:** [`Constraint<T>` + `Validator<T>`](./custom-validation.mdx)
    instances added via `.constrain()` are **not** translated to JSON Schema
    because there is no standard way to represent arbitrary logic.
-   **`additionalProperties`:** `Ack.object(..., additionalProperties: false)`
    becomes `additionalProperties: false`; `additionalProperties: true` is
    emitted as the boolean `true`.
-   **`Ack.map(valueSchema)`:** Exported as
    `{"type": "object", "additionalProperties": <value schema>}`. Map keys are
    always strings, so no `propertyNames` keyword is emitted.
-   **`Ack.any()`:** Runtime validation accepts non-null JSON-safe values.
    JSON-like adapter exports represent those JSON-compatible values and attach
    an `ack_any_json_boundary` warning to the `AckSchemaModel`.
-   **`Ack.lazy()` runtime checks:** Recursive structure is exported with
    Draft-7 `definitions` / `$ref`. Constraints and refinements added directly
    to the lazy reference are runtime-only and are reported as schema-model
    warnings rather than emitted beside `$ref`.
-   **Date/time range constraints:** Draft-7 has no standard `formatMinimum` or
    `formatMaximum` keywords. ACK validates `.min()` and `.max()` at runtime and
    records schema-model warnings instead of rendering non-standard keywords.
-   **List item nullability:** `Ack.list(...)` does not support nullable item
    schemas yet. Make the list itself nullable with `Ack.list(item).nullable()`
    when the whole field may be null.
-   **Discriminated branches:** `Ack.discriminated(...)` owns the discriminator.
    Branches may omit the discriminator field; compatible `Ack.literal(...)` or
    `Ack.enumString(...)` fields are accepted; generated branches expose the
    exact branch value as `const`.

## Integrating into API documentation

Use the generated JSON Schema map within a larger API documentation structure.

```dart
// Assume you have a function to build the full API spec
Map<String, dynamic> buildApiSpecification() {
  final userJsonSchema = userSchema.toJsonSchema();
  
  return {
    'schemas': {
      'User': userJsonSchema
    },
    'endpoints': {
      '/users': {
        'post': {
          'summary': 'Create a new user',
          'requestBody': {
            'required': true,
            'content': {
              'application/json': {
                // Reference the generated schema
                'schema': {
                  '\$ref': '#/schemas/User'
                }
              }
            }
          }
        }
      }
    }
  };
}

// Usage
final fullApiSpec = buildApiSpecification();
print(JsonEncoder.withIndent('  ').convert(fullApiSpec));
```

This keeps your validation logic and API documentation in one place.

## Advanced JSON Schema features

### Schema descriptions and metadata

Add descriptions and metadata to your schemas for better documentation:

```dart
final userSchema = Ack.object({
  'id': Ack.string().uuid().describe('Unique user identifier'),
  'name': Ack.string().minLength(1).describe('User\'s full name'),
  'email': Ack.string().email().describe('User\'s email address'),
  'age': Ack.integer().min(0).max(150).describe('User\'s age in years').optional(),
}).describe('Represents a user in the system');

final jsonSchema = userSchema.toJsonSchema();
// Output includes description fields
```

### Default values in JSON Schema

Schemas with default values include them in the generated JSON Schema:

```dart
enum Theme { light, dark }

final configSchema = Ack.object({
  'theme': Ack.enumValues(Theme.values).withDefault(Theme.light),
  'notifications': Ack.boolean().withDefault(true),
  'maxItems': Ack.integer().min(1).max(100).withDefault(10),
});

final jsonSchema = configSchema.toJsonSchema();
// Output includes "default" properties
```

### Complex schema patterns

JSON Schema generation works with all Ack schema types:

```dart
// Union types
final mixedValueSchema = Ack.anyOf([
  Ack.string(),
  Ack.integer(),
  Ack.boolean(),
]);

// Discriminated unions
final shapeSchema = Ack.discriminated(
  discriminatorKey: 'type',
  schemas: {
    'circle': Ack.object({
      'radius': Ack.double().positive(),
    }),
    'rectangle': Ack.object({
      'width': Ack.double().positive(),
      'height': Ack.double().positive(),
    }),
  },
);

// Nested arrays and objects
final complexSchema = Ack.object({
  'users': Ack.list(userSchema).minLength(1),
  'metadata': Ack.object({
    'version': Ack.string(),
    'tags': Ack.list(Ack.string()).unique(),
  }).optional(),
});

// All produce valid JSON Schema
final mixedJson = mixedValueSchema.toJsonSchema();
final shapeJson = shapeSchema.toJsonSchema();
final complexJson = complexSchema.toJsonSchema();
```
