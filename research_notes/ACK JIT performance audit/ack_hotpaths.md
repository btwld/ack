## 1. What do successful and failed validation paths actually do?

### Takeaway

ACK native `safeParse` is a general-purpose parser that constructs validated values and detailed diagnostics through recursive schema objects. Imported JSON Schema parsing has a lighter successful evaluator but first makes a detached, deeply unmodifiable JSON copy; neither operation is equivalent to Ajv's validation-only call. — [Native entry point](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/schema.dart:380>); [Imported parse](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:64>); [Ajv adapter](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/node/worker.mjs:69>)

#### Native failures and diagnostics

- Wrong-type scalar input returns a `TypeMismatchError` plus `Fail` before the normal constraint loop. Constraint failure creates a `ConstraintError` carrying the constraint, message, and a context map; the default context eagerly evaluates **`value.toString()`**. A collection-level failure can therefore stringify a large collection even though final error formatting is outside the benchmark loop. `SchemaConstraintsError` also eagerly joins messages; `SchemaNestedError` stores all child errors. — [Scalar mismatch](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/string_schema.dart:24>); [Constraint context](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/constraints/constraint.dart:96>); [Error construction](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/validation/schema_error.dart:86>)
- Native objects/lists collect sibling failures and continue processing. Successful siblings still create parsed output that is discarded when the parent fails. Constraints collect all violations; refinements run only after constraints succeed and stop at the first failed refinement. Reordering or fail-fast conversion would change observable behavior. — [Object failure](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/object_schema.dart:100>); [List failure](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/list_schema.dart:61>); [Constraints/refinements](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/schema.dart:153>)
- **Full JSON Pointer strings are already lazy.** A native success stores `SchemaContext` parent links, names and segments; the `path` getter recursively escapes/concatenates only when called. Error serialization calls it, not ordinary successful parsing. Repeated path access recomputes it; nested path rendering can revisit shared prefixes. Do not present “stop building full paths on every success” as a new optimization. — [Context/path](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/context.dart:29>); [Error path/toMap](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/validation/schema_error.dart:21>)
- A retained error retains a context chain and each context's `value`, including the root input. This makes **allocation rate**, **retained heap after failures**, and **error rendering** different questions; a caller storing one leaf error can retain a large input. — [Context fields](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/context.dart:7>); [Error stores context](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/validation/schema_error.dart:8>)

#### Imported JSON Schema paths

- `safeParse` creates a root context, then `_copyImportJson(value, HashSet.identity())` checks JSON safety/cycles while recursively copying all maps/lists into private backing containers and unmodifiable views. Strings, booleans, null and finite numbers are reused. It then evaluates the schema on that copy. The source already did this **before #213**, so do not credit #213 with inventing this parse-time fusion. — [Current parse](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:66>); [Copy routine](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/json_schema/json_schema_compiler.dart:650>); [Pinned pre-PR implementation](https://github.com/btwld/ack/blob/b740f6b1d8254982543dcd87a22bcf64df0e2bed/packages/ack/lib/src/schemas/imported_json_schema.dart#L66)
- The successful `_checkImportedNode` recursion returns `null`, not one `Ok`/context per node. Only the outer helper produces normal `SchemaResult` success and applies user-added constraints/refinements. This removes much native per-node metadata work, but validation still traverses the copied graph and unmodifiable views. — [Evaluator](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:210>); [Outer result](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:82>)
- The evaluator checks typed fields on every visited node, a type-list `.any` callback even for a single type, optional enum equality, combination keywords, and type-specific keywords. Properties use map lookups, list items recursive calls. Schema “compilation” here builds a typed node graph; it does not emit a schema-specific Dart function. — [Node representation](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/json_schema/json_schema_compiler.dart:29>); [Type compilation](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/json_schema/json_schema_compiler.dart:493>); [Evaluator](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:210>)
- Schema evaluation fails on its first violation, but even a root/first-child schema failure follows the entire JSON copy. JSON-safety failure therefore currently takes precedence over schema failure elsewhere in the document. Reordering validation before safety/copy can change error type/order and is not automatically behavior-preserving. — [Parse order](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:66>); [First-error return](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:287>)
- Failure creates `_ImportViolation` records and repeated `[segment, ...path]` / `[...tokens, ...evaluationPath]` lists while unwinding recursion, then builds public contexts and keyword pointer strings at the root. A single deep error can copy progressively longer lists. An `anyOf` success may still allocate discarded violations for earlier unsuccessful alternatives; `not`/`if`/`contains` likewise use full violation-producing checks for probes. — [Violation rebuilding](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:163>); [Probe branches](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:222>); [Public errors](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:86>)
- The active-identity set tracks the current recursion stack, not all previously seen objects; repeated shared subgraphs are allowed and copied for each occurrence. Cycles and non-finite numbers are rejected. Imported parsing expressly guarantees a detached recursively unmodifiable snapshot, including unconstrained JSON subtrees. Returning the original input, or a view over its mutable containers, would break this contract. — [Copy active set](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/json_schema/json_schema_compiler.dart:651>); [Snapshot contract](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:3>); [Snapshot/cycle/shared-value tests](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/test/json_schema_import_test.dart:738>)

### Inferences

- Native metadata and copied output are plausible allocation-rate drivers as item count increases; imported copying, wrapper access and schema-graph interpretation are different plausible drivers. - Because copied collections escape in parsed output while many result wrappers are immediately unpacked, reducing source-level `Ok` count might save less actual heap than it appears. A CPU flame graph plus allocation attribution is necessary before redesigning the result protocol. — [Composite result consumption](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/list_schema.dart:61>); [Output ownership](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/object_schema.dart:149>)

### Gaps

- No allocation bytes/op, allocations by class, JIT inlining/escape data, GC pauses, retained-heap snapshots, instruction counts, or stable idle-machine time series have been collected in this source-only audit.
- Source does not establish whether empty growable lists, closure environments, `MapEntry` values, record iterators, or `Ok` wrappers survive JIT optimization at each hot call site.

## 2. What did PR #213 improve, and where can large-payload behavior become pathological?

### Takeaway

PR #213 removes redundant collection copying and repeated interpreter bookkeeping, but keeps the parser's ownership/diagnostic model and imported evaluator architecture. The strongest *source-demonstrable* nonlinear risks are imported unique-item checking, deep map equality, deep failure-path rebuilding, and repeated recursive context scans—not ordinary flat-object validation. — [PR diff](https://github.com/btwld/ack/compare/b740f6b1d8254982543dcd87a22bcf64df0e2bed...82d21b0d27a8ee6ac6c06b9843ffaad9f7b91c51); [Imported uniqueness](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:336>); [Deep equality](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/utils/collection_utils.dart:89>); [Lazy depth scan](</Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/lazy_schema.dart:142>)

### Gaps

- No stable measurements presently distinguish linear slopes from allocation/GC thresholds as payloads exceed 500 items.

#### Semantics that an optimization cannot silently remove

- **Ownership:** native composite outputs use owned backing containers. Imported/`Ack.any()` have explicit deep detached snapshots.
