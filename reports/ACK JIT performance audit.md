## ACK performs copying and diagnostics that Ajv avoids

**Source-verified behavior, not measured allocation.** Native objects build a new validated map, check declared fields with missing-versus-null semantics, create child contexts, consume child results, scan unknown keys, and wrap private output storage in an unmodifiable view. Lists similarly build typed output, visit every child, and apply list constraints afterward. The shared constraint helper creates an initially empty error list even on ordinary success. For the historical nested shape, native traversal visits **`4N + 3` schema nodes**: root object, identifier, list, and an object plus three scalars per item. At 500 items that is 2,003 source-level context/result/helper visits, not 2,003 proven heap allocations: the JIT can eliminate intermediates. ([Object parsing](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/object_schema.dart:40); [list parsing](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/list_schema.dart:33); [constraint helper](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/schema.dart:147); [corpus shape](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/corpus.py:26))

Imported parsing has a different cost structure. It first checks JSON safety and cycles while copying the entire input into a **detached, recursively unmodifiable snapshot**, then evaluates a typed schema-node graph. Successful recursive evaluation returns `null`, avoiding native-style success wrappers and contexts at every node, but it still performs copy traversal followed by schema traversal. The active identity set detects cycles along the current recursion stack; repeated shared subgraphs remain legal and are copied per occurrence. An early schema failure still follows the complete copy. This ordering gives JSON-safety failures precedence and makes “validate first, copy only on success” a behavioral change, not an automatically safe optimization. ([Imported parse](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:64); [copy implementation](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/json_schema/json_schema_compiler.dart:650); [snapshot/cycle tests](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/test/json_schema_import_test.dart:738))

Ajv instead compiles and optimizes a code representation, renders JavaScript, and creates a function with `new Function`. Reusing that function amortizes compilation. Its success path starts with a null error array and allocates diagnostic storage when failures occur; the admitted normal validation path does not clone the input. That architecture gives V8 an explicit, schema-specific function rather than repeatedly interpreting schema nodes. It does not prove every Ajv keyword is allocation-free. ACK's existing generated facades delegate to runtime parsing, so the presence of `ack_generator` does not provide equivalent specialization. ([Installed Ajv compiler](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/node/node_modules/ajv/lib/compile/index.ts:162); [Ajv error construction](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/node/node_modules/ajv/lib/compile/errors.ts:90); [schema reuse guidance](https://ajv.js.org/guide/managing-schemas.html); [ACK generated facade](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack_generator/lib/src/builders/class_model_emitter.dart:218))

PR #213 already removed a second collection copy by using unmodifiable views over privately created backing storage. It also replaced repeated imported-keyword lookups with typed node fields and simplified schema-document copying during construction. **JSON-safety checking and copying were already fused before the PR**; this is distinct from schema-evaluation/copy fusion, which remains proposed. Lazy export rendering and encode changes are outside this comparison's measured operations. These attribution boundaries prevent recommending already-completed work or crediting validation timings to an unmeasured path. ([PR diff](https://github.com/btwld/ack/compare/b740f6b1d8254982543dcd87a22bcf64df0e2bed...82d21b0d27a8ee6ac6c06b9843ffaad9f7b91c51); [baseline imported parse](https://github.com/btwld/ack/blob/b740f6b1d8254982543dcd87a22bcf64df0e2bed/packages/ack/lib/src/schemas/imported_json_schema.dart#L66))

Error costs deserve their own investigation. Native JSON Pointer strings are **already lazy**, but contexts retain parent links and input values; retaining a leaf error can therefore retain the root input. Constraint error construction eagerly calls `value.toString()` in its default context, and aggregated constraint messages are joined eagerly. Large collection failures can incur substantial string work even though final report formatting is outside timing. Imported failure unwinding repeatedly prepends path segments into lists, and branch probes can build violations later discarded by a successful `anyOf`. Allocation churn, retained-input memory, and error rendering are three distinct concerns. ([Context/path implementation](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/context.dart:7); [constraint context](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/constraints/constraint.dart:96); [error constructors](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/validation/schema_error.dart:86); [imported violations](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/packages/ack/lib/src/schemas/imported_json_schema.dart:163))

## Runtime representation makes specialization valuable but not sufficient

The installed Dart 3.13.4 SDK is pinned to revision `b530c21f7de367b94fb04787bfed9d8e989d75e8`. Its JIT collects feedback, optimizes hot functions, performs speculative inlining and allocation sinking, and can replace running-loop code through on-stack replacement. Therefore counting constructors is not allocation profiling, and a short elapsed-time warmup on an overloaded machine does not demonstrate optimized steady state. Polymorphic schema dispatch is a plausible optimization obstacle, but no inspected feedback or deoptimization trace yet proves it dominates ACK. Adding `final`, casts, or forced-inlining pragmas is not a substitute for evidence. ([Pinned VM architecture](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/docs/README.md); [installed SDK revision](/Users/leofarias/fvm/versions/stable/bin/cache/dart-sdk/revision))

Dart's VM JSON decoder creates string-keyed compact maps implementing `LinkedHashMap`; ordinary key access uses its map lookup machinery. V8 documents HiddenClasses and inline-cache-friendly property access for suitably shaped objects. A generated JavaScript `data.name` is consequently not mechanically identical to a Dart decoded-map lookup. A specialized Dart function can remove schema interpretation while retaining map lookup and output-construction costs. These are source-backed architectural differences, **not a measured attribution to a particular V8 object representation**. Stable versus reordered keys and optional-field mixtures remain useful tests. A separate runtime inventory records V8 `14.6.202.34-node.21`; it does not verify the actual representation of these objects. ([Pinned Dart JSON parser](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/sdk/lib/_internal/vm/lib/convert_patch.dart#L155); [compact map](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/sdk/lib/_internal/vm_shared/lib/compact_hash.dart#L671); [V8 fast properties](https://v8.dev/blog/fast-properties); [runtime inventory](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/.context/benchmark-jit-scaling-2026-10-08/node-runtime-versions.json))

Both runtimes use generational garbage collection. Dart's pinned collector includes a parallel stop-the-world young-generation scavenger and concurrent old-generation work. Cheap short-lived allocation can still consume allocation bandwidth and trigger collection; retained outputs or errors change promotion and liveness. Stable post-GC memory does not imply low allocation, while growing RSS does not alone prove a leak. Distinguish current heap, retained size after collection, allocation samples, external memory, and RSS. The current benchmark retains only the latest result; applications retaining many parsed results or failures are a separate lifetime workload. ([Dart GC](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/docs/gc.md); [V8 GC](https://v8.dev/blog/trash-talk); [DevTools memory definitions](https://docs.flutter.dev/tools/devtools/memory); [Node memory metrics](https://nodejs.org/api/process.html#processmemoryusage); [result retention](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/dart/lib/adapters.dart:38))

JSON ingress is another independent layer. Current decode+validate starts from an existing language string, excluding network/file I/O and UTF-8 byte decoding. Dart has a fused UTF-8/JSON decoder path, but evaluating it requires a separately labeled byte-ingestion workload. Replacing maps with typed models also adds conversion unless inputs already have that representation; report conversion plus validation rather than hiding the first pass. ([Pinned fused decoding](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/sdk/lib/_internal/vm/lib/convert_patch.dart#L45); [worker phases](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/dart/bin/worker.dart:56))

## Larger payloads must separate slopes, phases, and lifetimes

**The length sweep is complete; additional axes remain proposed.** The JIT-only scaling cohort measured **1, 10, 100, 1,000, and 10,000 items** under a fixed schema whose `maxItems` covers the largest size. Each size includes valid, first-invalid, last-invalid, all-invalid, and decode+validate cases. Four varying payloads per case bound fixture memory, and metadata records compact UTF-8 size, not heap size. This corpus is not interchangeable with the historical one. Larger sizes still require a memory/time pilot; extending beyond 10,000 does not answer width, depth, representation, or lifetime questions. ([Completed scaling evidence](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/.context/benchmark-jit-scaling-2026-10-08/results.json); [scaling corpus](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/benchmarks/corpus.py:151))

A useful hypothesis is `T ≈ fixed setup + decode + per-node work + output construction + errors + GC + scheduling`. Increasing N amortizes fixed costs but multiplies per-node differences; if ACK's slope is steeper, larger payloads widen the absolute gap. Estimate latency/node and throughput against **both node count and serialized bytes**, and inspect discontinuities rather than fitting one universal line. Separate-phase medians need not sum to the combined median because JIT, caches, and GC interact. With length now measured, extend the reference sweep through these orthogonal controls.

| Experiment | Discriminating observation | Essential correctness/control |
|---|---|---|
| Fixed item shape, increasing count | Linear slope versus GC/cache thresholds | Same constraints; valid maximum and first rejected size; bounded fixtures |
| Width at similar total nodes; include 199/200/201 required fields | Map/traversal cost versus generated-code thresholds | Ajv defaults `loopRequired`/`loopEnum` to 200; save schema/source size and compile cost |
| Depth 1/4/16/64 | Path rebuilding, recursion scanning, stack sensitivity | Explicit depth/time limits; distinguish lazy-schema recursion caps |
| First/middle/last failure and invalid density | Traversal and diagnostic cost | Report error counts/topology, not an “equal all-errors” ranking |
| Stable/reordered keys, optional omissions | Representation/JIT-feedback sensitivity | Byte-identical shared inputs and equal acceptance |
| Long ASCII, then separate Unicode/numeric-edge cohorts | Byte scanning versus node overhead | Native length uses code units; imported bounded length uses code points |
| Distinct/duplicate `uniqueItems`, wide map `const`/`enum`, branch breadth | Explicit nonlinear algorithms | Structural numeric equality, collision handling, branch order |

### Profiling must not mistake a heap census for allocation rate

The completed driver prepared and warmed data, marked operation windows, consumed results, and stayed alive for export. Decode-only and decode+parse controls ran; targeted allocation tracing, controlled retention, and exact imported-copy/evaluator controls remain future work. The JSON round-trip control is not ACK's snapshot algorithm and cannot establish its ownership cost. Captures report a 1,000 µs sampling period; no selected stack reported truncation. Raw samples, window metadata, and separate corrected views preserve interpretation. ([Diagnostic inventory](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/.context/jit-profile-summary.md); [round-trip semantics](/Users/leofarias/conductor/workspaces/ack/edinburgh-v1/.context/jit-profile-clone-1000/profile.json))

**Critical Dart 3.13.4 tooling trap:** VM-service documentation describes `accumulatedSize` and `instancesAccumulated` as cumulative counters, but this SDK's `ClassTable` implementation fills them with the same current-heap census values as `bytesCurrent` and `instancesCurrent`. `reset:true` updates a timestamp; it does not restore cumulative allocation accounting. Consequently, **do not divide these fields or their deltas by operation count and report bytes allocated/op**. Before collection, a census can also include unreachable objects not yet reclaimed. True allocation-byte accounting remains an open tooling requirement unless a separate supported mechanism is validated. ([Protocol wording](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/vm/service/service.md#classheapstats); [actual heap-stat serialization](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/vm/class_table.cc#L321); [reset behavior](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/vm/service.cc#L4737))

The HTTP/RPC controller has a related implementation caveat: `getAllocationProfile` rejects present `gc` or `reset` parameters unless they are true. **Omit unwanted parameters; do not send `gc=false` or `reset=false`.** Use `gc:true` only in a separate retention pass, never inside throughput loops. Targeted `setTraceClassAllocation`/`getAllocationTraces` can identify context, result, list/map, and error allocation sites, but tracing perturbs execution and samples can fail or overrun buffers; report observed samples, not an exhaustive count. Node's `--heap-prof` is sampled too. Retained-size snapshots and GC timeline correlation answer different questions from allocation throughput. ([Service parameter handling](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/vm/service.cc#L4742); [allocation-sampling failure path](https://github.com/dart-lang/sdk/blob/b530c21f7de367b94fb04787bfed9d8e989d75e8/runtime/vm/profiler.cc#L1187); [Node heap profiling](https://nodejs.org/api/cli.html#--heap-prof-interval))

## Optimize existing safeParse before changing the contract

**Ranked proposals, not implemented speedups.** Select the first measured avoidable cost, change one mechanism, and retain success values, input ownership, error order/paths, callback counts, and exception behavior. Imported parsing promises deep snapshots; native known composite fields use owned output, but native `additionalProperties: true` currently forwards unknown values by reference. Preserve that actual behavior rather than assuming universal deep freezing. Defaults, lossless integral-double normalization, and codecs' boundary/decode/runtime-validation lifecycle also prohibit a universal “just check predicates” shortcut. A fast check followed by replay on failure must not execute user callbacks twice. ## Conclusion

The decisive next question is **how much avoidable work remains while preserving ACK's useful contract**. A controlled JIT experiment can distinguish output ownership, generic execution, decoding, and diagnostic lifetime instead of treating one cross-language ratio as a single problem. If required output construction dominates, retain that contract and target redundant work; if metadata or an explicit quadratic algorithm dominates, pursue a compatible engineering improvement. That distinction turns “get closer to Ajv” into a falsifiable optimization program without making ACK faster by quietly doing less.
